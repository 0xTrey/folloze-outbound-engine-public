Folloze Architecture Reference

How the Folloze Outbound Engine Actually Works

A readable call-ready outline of the current system: how contacts get sourced, how outbound runs, how Folloze engagement becomes signal memory, and what controls determine whether the engine is actually allowed to launch.

Sourcing + research Apollo provides accounts and contacts. Research layers add company, persona, and timing context before copy is generated.
Execution spine The current live path is still a classic outbound engine: source, reveal, research, generate, enroll, and monitor.
Context spine Salesforce Tasks, Folloze CSVs, and content metadata now feed a signal engine that interprets what buyers actually cared about.
Operational control The engine now distinguishes warming infrastructure from live sending, and it blocks enrollment when campaigns or mailboxes are not ready.

Workflow View

This view is intentionally linear so it prints and talks through cleanly. The idea is to show the system as a sequence of layers, not a dense all-at-once architecture map.

  • Sourcing and research
  • Outbound execution
  • Behavior and engagement signal
  • State and follow-up intelligence
  • Launch and operator control
01

Account Sourcing

Start with who should enter the engine.

Inputs

  • Apollo account search against the ICP
  • Buying-committee contacts by role and persona
  • Account fit and priority scoring
  • Sequence-family assignment in Neon

What gets written

  • accounts and contacts
  • campaign_assignments
  • sequence_families routing
02

Research + Payload Build

Turn raw prospects into sendable copy inputs.

Current execution path

  • reveal_emails finds verified addresses
  • enrich_research collects company and persona context
  • build_payloads generates T1 copy and static follow-up payload fields

System output today

The engine currently stores approved personalization payloads in Postgres and uses those as the direct input to Smartlead enrollment.

03

Outbound Transport

Push approved leads into the delivery layer.

What Smartlead does

  • holds campaigns and sequences
  • rotates across assigned inboxes
  • tracks replies, clicks, and bounces
  • acts as the mail transport layer

Important architectural point

Smartlead is no longer the strategy brain. The repo is moving toward using Smartlead only as transport plus telemetry, while the engine decides what follow-up should say.

04

Board Experience + Engagement Capture

Folloze turns outbound traffic into observable first-party behavior.

What the buyer does

  • lands on a Folloze board from outbound
  • views assets, spends time, clicks CTAs, revisits
  • shows which topics, themes, and proof points resonate

What the system can observe

  • board visits and repeat visits
  • item views and duration
  • CTA clicks and anchor clicks
  • account-level and multi-stakeholder engagement
Why this matters

This is the core differentiator. The engine is not just sending emails. It is using outbound to create first-party intent and behavioral evidence.

05

Signal Engine

Normalize behavior into durable memory and follow-up inputs.

Inputs

  • Salesforce Folloze Task ingestion
  • Folloze People Engagement CSV snapshots
  • Folloze content catalog and asset summaries
  • email telemetry and research evidence

Durable state written

  • signal_events
  • asset_catalog
  • contact_signal_state
  • account_signal_state
  • outbound_briefs
Raw events board views, asset views, CTA clicks, replies
Derived facts what changed, what resonated, what theme is forming
Interest memory current contact and account state
Outbound brief why now, angle, proof, CTA, send gate
Follow-up copy eventual just-in-time T2 and T3 generation
Outcome reply or engagement feeds back into memory
06

Launch Controls

Separate infrastructure readiness from actual sending.

Infrastructure prep

  • warmup_smartlead_inboxes turns on warmup and daily caps
  • sync_smartlead_mailboxes syncs live inbox state into Postgres
  • campaign mailbox assignments can be reconciled without sending leads

Send gate

  • engine pause file must allow sending
  • sequence family must be active
  • Smartlead campaign must be active, not paused or completed
  • assigned mailboxes must be warmed and not too fresh
Pause layer ops/engine-paused.json can block all enrollment.
Campaign layer Even with good inboxes, paused Smartlead campaigns still block launch.
Mailbox layer Fresh inboxes may warm successfully but still be intentionally blocked from cold enrollment.

What is live now

The sourcing, research, payload generation, Smartlead plumbing, Salesforce/Folloze signal ingestion, signal-state derivation, outbound brief gating, mailbox sync, and inbox warmup automation are all built and operating.

What is still transitioning

The engine is not fully at “signal-driven autonomous follow-up” yet. The big next step is replacing static T2/T3 copy with just-in-time follow-up generation from current signal state.

Simple one-liner

The outbound engine uses targeted outreach to drive buyers into a Folloze experience, then turns that engagement into stronger follow-up and account intelligence.

What makes it different

It is not just an email sequencer. It is an outbound system that is being rebuilt around first-party engagement memory.

Best way to frame it on the call

Lead with the execution spine first, then explain that the signal engine is the layer that makes later touches smarter and more defensible.
